# Risk Register — Dynamic Flow-mode Redesign

Governing skill: `skills/sdlc/sdlc-requirements/SKILL.md` (every mitigation must be testable, not a vibe) and `skills/meta/karpathy-guidelines/SKILL.md` (surface assumptions, verifiable success criteria).

**Rules for this register**

- `likelihood` / `impact` ∈ {Low, Med, High}; High × anything is triaged first.
- `owner` is a team-lead ID from `docs/agent-team/HIERARCHY.md` — one named lead per row, no teams, no "everyone".
- `verify hook` is an **exact, runnable command or grep** that proves the mitigation exists (or fails loudly when it regresses). A row without owner **and** verify hook is invalid — the hook is the point of the register.
- Hooks referencing `crates/gui/src/flow/` are forward-looking: that module lands with the redesign, so those hooks pass once (and only while) the mitigation is in place. Hooks on existing files (R-03, R-06, R-09) pass today.

| id | risk | likelihood | impact | mitigation | owner | verify hook |
|---|---|---|---|---|---|---|
| R-01 | Animation repaint storms and battery drain: flow animation calls unconditional `request_repaint()` every frame, so the UI keeps repainting while idle or in the background | Med | High | Flow repaints only while a transition is active via `ctx.request_repaint_after(frame budget)`; the loop idles at rest and when the window is unfocused; no unconditional per-frame `request_repaint()` anywhere in flow code | TL-GRAPH | `grep -c request_repaint_after crates/gui/src/flow/*.rs` |
| R-02 | Frame-time spikes and visible stutter on very large graphs (>2k nodes): per-frame layout and paint cost grows with node and edge count | High | High | Hard LOD gate `NODE_LOD_THRESHOLD = 2_000` — above it the flow renderer draws simplified nodes/edges with throttled layout steps; a perf test asserts the frame budget on a synthetic 5k-node graph | TL-GRAPH | `grep -rn "NODE_LOD_THRESHOLD" crates/gui/src/flow/*.rs && cargo test -p repowalk-gui --locked --test flow_frame_budget` |
| R-03 | Scope creep past the feature freeze: flow work silently absorbs extra features (new view modes, theming, export tweaks) after freeze | Med | High | The `repowalk-scope` freeze rule is binding — nothing new after feature freeze; every proposed addition first becomes a board REQ task with checkable acceptance criteria, and the explicit out-of-scope fence stays in the requirements doc | TL-PROD | `grep -c "feature freeze" skills/repowalk/repowalk-scope/SKILL.md && grep -c "Out of scope" board/docs/requirements.md` |
| R-04 | No-network guarantee broken by a future dependency pulling `reqwest`/`tokio`/`hyper` transitively (manifests look clean, the tree does not) | Med | High | Network crates stay on the forbidden list (`repowalk-stack`); any new crate is checked against the pinned stack first; the check inspects the full workspace dependency tree, not just `Cargo.toml` files | TL-BLD | `cargo tree --workspace --locked \| grep -c reqwest` |
| R-05 | Reduced-motion and accessibility: animation is the only carrier of step/state information, excluding users with OS reduced-motion enabled and screen-reader users | Med | High | Honor OS `prefers-reduced-motion` plus an in-app motion toggle (animation collapses to instant state changes), and render every flow state also as a non-animated `state_label` text string with keyboard step controls — animation is decoration, never the only signal | TL-DSN | `grep -rn "reduced_motion" crates/gui/src/flow/*.rs && grep -rn "state_label" crates/gui/src/flow/*.rs` |
| R-06 | Multi-team ownership conflicts on shared files (`crates/gui/src/app.rs`, `Cargo.toml`, workflows): parallel agents on `redesign` overwrite each other's edits | Med | Med | Single-writer discipline: one writer per board task, design.md single-writer model; shared files are edited only by the team named as owner in this register, conflicts arbitrated through the task board, never by racing edits | TL-BLD | `grep -c "single-writer" board/docs/design.md && grep -c "one writer per task" skills/meta/agent-board/SKILL.md` |
| R-07 | Golden-fixture churn: flow output changes ripple into `fixtures/golden/index.json`, turning every unrelated change into a fixture fight | High | Med | Fixture regeneration is explicit-only (`UPDATE_GOLDEN=1`) and the fixture diff is reviewed in the same change; a normal test run must leave `fixtures/golden/` byte-identical; volatile fields (repo root, timestamps) stay normalized | TL-VER | `cargo test -p repowalk-core --locked --test golden && git diff --quiet -- fixtures/golden/` |
| R-08 | Unbounded playback memory on long traces: playback buffers every step and rendered frame of a long walk, growing without limit toward OOM | Med | High | Playback history is a capped ring buffer `MAX_PLAYBACK_FRAMES` with drop-oldest eviction; only the window around the playhead is retained; no full-trace vector of rendered frames | TL-GRAPH | `grep -rn "MAX_PLAYBACK_FRAMES" crates/gui/src/flow/*.rs` |
| R-09 | Dependency pin drift: eframe/egui/egui_graphs bumped mid-redesign, breaking flow rendering and the vendored `egui_code_editor` patch | Low | High | Versions pinned per `repowalk-stack` (eframe/egui 0.36, egui_graphs 0.32.0) with the vendored serde patch; any bump is its own task gated on the full test suite plus a flow smoke run before merge | TL-BLD | `grep -c '^eframe = "0.36"' crates/gui/Cargo.toml` |
| R-10 | Untestable motion behavior: animation logic embedded in paint code ships silent regressions because nothing asserts it | Med | Med | Flow state machine kept as a pure function of (state, elapsed ms) in a dedicated module with deterministic unit tests; the render layer only paints its output, so behavior is testable without real frames | TL-VER | `grep -rn '#\[test\]' crates/gui/src/flow/state.rs` |
| R-11 | Parallel edits on the `redesign` branch break the workspace mid-flight, blocking every other agent working on the redesign | Med | High | Every agent runs the verification gate before declaring done (`docs/agent-team/VERIFICATION.md`): formatting and a workspace check must pass; a red tree is `blocked`, never `done` | TL-VER | `cargo fmt --all -- --check && cargo check --workspace --locked` |

**Expected hook results**

- Non-zero matches (≥1): R-01, R-02 (first clause), R-03, R-05, R-06, R-08, R-09, R-10.
- Zero matches / exit 1 from `grep -c` is the *pass* condition: R-04.
- Exit 0 with no diff is the pass condition: R-07 (`git diff --quiet`), R-11.
- R-02 second clause and R-07 first clause pass only while the perf test and golden test exist and are green.

**Out of scope of this register:** code changes (mitigations land with their owning teams' tasks), performance numbers (captured by R-02's test), and non-flow risks already tracked in `board/docs/design.md` §6.

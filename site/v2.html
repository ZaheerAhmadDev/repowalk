v2 · complete understanding suite

Open any codebase. Understand all of it.

v2 learns the repo once, then answers the whole set of questions in seven moves — learn → inventory → control flow → connections → structure → usage → export. Still pure static analysis: no AI, no network, no keys.

The suite at a glance

  1. Learn — index the repo and cache the analysis.
  2. Inventory — LOC, languages, entrypoints, complexity, hotspots, god files, cycles.
  3. Control flow — a CFG per function: branches, loops, match arms, cyclomatic badge.
  4. Connections — the call/import graph with real names, clusters and filters.
  5. Structure — type diagrams (structs/enums/traits/classes) and the module DAG.
  6. Usage — per-file variables with read/write counts and highlight-all-uses, plus find-all-references.
  7. Export — Mermaid / DOT / SVG and a self-contained Markdown report.
  8. Health, Notes & 101 — guardrail findings, bookmarks that travel with the checkout, and a thirty-second orientation card.

Capabilities in detail

Engine and surface, with what shipped.

Learn

Walk → parse → resolve → analyze → cache, with per-phase counts and a per-file incremental cache so a re-learn only re-parses what changed.

Working — learn.rs plus the CLI; the Repo 101 panel shipped.

Inventory

Cyclomatic complexity and max nesting per function, per-file fan-in/out, hotspot ranking, god files and cycles.

Working — complexity.rs / metrics.rs; Health v2 panel shipped.

Control flow

Per-function CFG with Entry/Block/Branch/Loop/Match/Call/Return/Exit nodes and normal|true|false|back edges, plus a cyclomatic badge.

Working — Rust/Python/TS CFGs pass their goldens; Diagrams → Control flow shipped.

Connections

Graph v2: readable real symbol names, clustering by module, layout modes, filters, focus+context dimming, and honest dashed ? edges for unresolved calls.

Working — real-name labels with zoom level-of-detail, clustering, and an “exact only” filter shipped.

Structure

Type diagram (struct/enum/trait/class with fields, methods and containment/impl/inheritance edges) and the modules DAG (crate/dir/module with import edges, cycles tinted).

Working — types.rs, modules.rs; Types and Modules diagram views shipped.

Usage

Per-file variable table — name, kind, declared type, declaration line, scope, reads / writes / uses, first/last use, enclosing symbol — and find-all-references for any symbol.

Working — variables panel + highlight-all-uses, refs panel + jump-to-source shipped.

Export

Mermaid, DOT/Graphviz and hand-rolled SVG for every diagram, plus a generated architecture report in self-contained Markdown; PNG stays.

Working — one shared emitter model used by both GUI and CLI, so outputs cannot drift.

Guardrails (F15)

A small rules.json is checked and appended to the report; an Error finding fails repowalk report with a nonzero exit, so it drops into CI.

Working — rules.rs with the four rule kinds (forbid imports, cycles, max cyclomatic, max file LOC).

Deliberately not in v2, and the honest limits

Non-goals: no AI or LLM summaries, no refactoring or automatic edits, no git-diff / watch mode, no Tauri or web port, and no network use at all — the binary contains no HTTP client and no telemetry.

Known limits: an edge the analyzer cannot resolve is drawn dashed with a ?, and a cross-file reference is listed as name-only rather than presented as confirmed; a graph stops at 400 nodes and says what it hid instead of drawing a blank canvas.

The full feature list is F1–F15; see the repository docs/ for the plan, the execution map and the demo runbook.
